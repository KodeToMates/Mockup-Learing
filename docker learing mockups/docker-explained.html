1What is Docker?

Docker is a tool that packages your app plus everything it needs (language runtime, libraries, settings) into one portable unit called a container.

Think of a shipping container
📦
Before Docker
Ship goods loose. Every port handles them differently. Things break.
➜
🚢
With Docker
Put goods in a standard box. Any ship, truck or crane handles it the same way.
The classic problem Docker solves: "It works on my machine!" With Docker, if it runs in the container on your laptop, it runs the same on your teammate's PC, a test server, or the cloud.

2Why do you need it?

Real situations where Docker saves you time.

🗄️
Run databases instantly

Postgres, MySQL, Redis, MongoDB in one command. No installer, no leftovers on Windows.

🔁
Same setup everywhere

New teammate? docker compose up and the whole project runs.

🧪
Try tools safely

Test any software, then delete it. Your laptop stays clean.

🧩
Avoid version conflicts

Project A needs Node 16, project B needs Node 22? Each gets its own container.

🚀
Easy deployment

Build an image once, run it on any server or cloud service.

⚡
Fast & light

Containers start in seconds and use far less memory than full virtual machines.

8Ports and Volumes

Two things beginners always ask about.

🔌 Ports: -p 8080:80
🌐 Browser
localhost:8080
🐳 Container
nginx on port 80

Format is HOST:CONTAINER. The container is isolated, so you must "publish" a port to reach it from your browser.

💾 Volumes: -v mydata:/var/lib/postgresql/data
🐳 Container
deleted anytime
💽 Volume
data survives

Container storage disappears when the container is removed. A volume keeps data (like database files) safe outside it.

🌱 Environment variables: -e KEY=value

Pass settings such as passwords or modes into a container, for example -e POSTGRES_PASSWORD=secret.

9Docker Compose

Run several containers (app + database) with one file and one command.

# docker-compose.yml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://postgres:secret@db:5432/app
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - dbdata:/var/lib/postgresql/data

volumes:
  dbdata:
Commands
docker compose upStart everything
docker compose up -dStart in background
docker compose logs -fWatch logs
docker compose downStop and remove
docker compose down -vAlso delete volumes
Inside compose, containers reach each other by service name (here the app talks to db, not localhost).
