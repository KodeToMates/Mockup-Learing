1What is object storage?

A different way of thinking about files: not folders on a hard drive, but one flat bucket full of named files you fetch over the internet.

🗄️
Filesystem thinking
Nested drives and folders: C:\sites\client\images\hero.jpg. The path is the location.
➜
🪣
Object storage thinking
One flat bucket holding many objects, each with a unique key: images/hero.jpg. No real folders, no server to manage.
Object storage is built for exactly one thing: storing and serving files reliably at any scale, reachable over plain HTTP(S) — which is why it is the default place to put a website's images, video and user uploads.

4Access control: public vs private

Buckets and objects are private by default. You choose what, if anything, becomes reachable by anyone with the link.

🔒
Private (default)
Requesting the direct URL returns 403 Forbidden. Nobody can read it without permission.
vs
🌐
Public
Requesting the direct URL returns 200 OK with the file. Anyone with the link can read it, forever.
🔑 The escape hatch: presigned URLs

Instead of making a whole object public, you can generate a URL that grants temporary, scoped access to just that one object — useful for letting a client download a private invoice or an unreleased draft video without creating them an account.

5Practical use cases for an agency

  
What actually ends up in a bucket on a typical project.

  

    
🖼️
Website assets
Images, fonts, CSS/JS bundles served to every visitor.

    
📤
User uploads
Profile photos, attachments, form submissions from the app's own users.

    
🎬
Video & media
Larger files that benefit from a CDN rather than living on a web server.

    
🗃️
Backups & exports
Database dumps, client reports, anything you need kept but rarely touch.

    
🌍
Static site hosting
An entire static site served straight out of a bucket, no server at all.

7Amazon S3 vs Cloudflare R2

  
Both are object storage. The differences that actually matter day to day:

  

    

      
DimensionAmazon S3Cloudflare R2

      
        
APIDefines the de facto object storage APIS3-API-compatible — most existing S3 SDKs/CLIs work by changing the endpoint and credentials

        
Pricing shapeCharges for storage, requests, and data transferred out (egress)Charges for storage and requests; built around little to no egress fees

        
EcosystemDeep integration across AWS: CloudFront, Lambda, IAM, event notifications, many regionsRides Cloudflare's global network: integrates naturally with Cloudflare's CDN, Workers and Access

        
Typical CDN pairingUsually fronted by CloudFrontUsually fronted by Cloudflare's own CDN

        
DurabilityDesigned for very high durability via replication across multiple facilitiesDesigned for very high durability via replication across multiple facilities

8Common mistakes & best practices

  
The mistakes that actually cost agencies money or cause an incident.

  
Accidentally public buckets. The single most common and most costly mistake. Keep "block public access" on unless you specifically mean to serve a bucket publicly, and double-check before you flip it off.

  
Serving traffic directly from the bucket. Works fine at low traffic, but skipping a CDN means every visitor hits the origin directly — egress costs and latency both climb fast once a client site gets real traffic.

  
No lifecycle rules. Old backups, logs and draft uploads pile up forever and quietly inflate the bill. Set a rule to expire or archive what you no longer need.

  
Overly broad credentials. Giving an app or teammate full account access instead of a scoped, bucket-only policy turns one leaked key into a much bigger incident than it needed to be.
