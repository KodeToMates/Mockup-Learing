1What is HTTP?

HTTP (HyperText Transfer Protocol) is the set of rules a client (browser, app) and a server follow to exchange web pages, images and data. It works in simple pairs: one request, one response.

Think of ordering at a restaurant
💻
Client
browser / app
(the customer)
➜ Request: "GET /menu"⬅ Response: "200 OK + menu"
🖥️
Server
website / API
(the kitchen)
HTTP is stateless: the server does not remember you between requests. That is why cookies and tokens exist (section 7).

3HTTP methods

The method tells the server what you want to do. Click one.

Safe = does not change data (GET). Idempotent = repeating it gives the same result (GET, PUT, DELETE). POST is neither, so double-clicking "Pay" can charge twice!

4HTTP vs HTTPS

HTTPS = HTTP + TLS encryption. Same messages, but wrapped in a locked envelope so nobody in the middle can read or change them.

🔓 HTTP port 80 · plain text

Anyone on the same Wi-Fi, ISP or router can read your passwords, cookies and forms, and even inject ads or malware.

🔒 HTTPS port 443 · encrypted

Data is encrypted, the server proves its identity with a certificate, and tampering is detected. Browsers show a padlock.

7Headers, cookies & caching

  
Headers are labelled notes attached to each message.

  

    
Content-Type
What the body is: application/json, text/html, image/png.

    
Authorization
Proves who you are: Bearer <token>. Missing or wrong gives 401.

    
Cookie / Set-Cookie
Server hands you a small value, browser sends it back each time so the server "remembers" you. Use Secure; HttpOnly.

    
Cache-Control
max-age=3600 lets browsers reuse the response for an hour without asking again.

    
Location
Used with 301/302 redirects: tells the browser the new URL.

    
User-Agent / Accept
Who is asking, and which formats they can handle.
